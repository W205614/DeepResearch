### 发现与处理

1. `live-redis` 的首次扩展 E2E 为 `insufficient`。后续重跑分别暴露结构化输出 `json_invalid`、`Judgment` 列表长度超限及 `ClaimCheck.reason` 文本超限。将容器模型的数据边界放宽到可容纳实际回答，同时在提示词要求简短表达，并增加对应 provider 回归测试。单次修订后重跑通过；真实模型波动仍需保留为试用风险。
2. 本机验收脚本原先固定要求旧迁移 `0010_outbox_leases` 且断言内部模型处理必须关闭，与本机当前迁移和配置不符；现改为读取源码迁移头及实际配置。冒烟和验收脚本均可指定本机端口。
3. 界面数据策略说明已修正；导出下载逻辑延迟释放 Blob URL，并补充浏览器 ZIP 下载测试。浏览器工具未能稳定观察下载事件，Playwright 下载测试通过；因此不把它记为已确认的导出故障。

## 并发验证

压力测试使用隔离的 `dr-perf` Compose、64 个临时 OIDC 身份和确定性 Agent/模型/搜索上游；结束后仅删除其专属测试卷，默认项目的数据卷保留。测试重点是 API 控制面、限流、舱壁、熔断及任务链，**不代表真实模型生成吞吐量**。

| 负载 | 观察结果 |
| --- | --- |
| 持续 `GET /api/threads`，30 秒、200 次/秒 | 6001 次执行均为 200；正常请求 P95 7.22 ms。 |
| 同上，250 次/秒 | 7501 次执行均为 200；正常请求 P95 2.70 ms。 |
| 同上，300 次/秒 | 9001 次执行中 7748 次 200、1253 次 429/503；无其他状态，属于保护性拒绝。 |
| 5 秒 ramp，目标 500 次/秒 | 2500 次最终返回 200，但完成耗时 21.07 秒，实际约 118.63 次/秒，P95 18.64 秒；不能计作通过 500 次/秒容量。 |
| 单租户 100 次/秒与慢上游 | 200 次中 121 次 429；24 次慢上游调用中 16 次快速 503、8 次 200；同时控制路径 20/20 为 200，熔断后恢复。 |
| 并发业务正确性 | Java 幂等/准入、Outbox lease、报告审核并发测试通过；隔离 Docker 集成测试 4 通过，含扫描/索引/删除竞态。两条确定性研究任务完成。未观察到服务崩溃或死锁，但有限测试无法证明不存在其他竞态。 |
