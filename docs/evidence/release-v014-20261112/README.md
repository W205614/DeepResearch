## 最终失败后的离线修复

原始供应商响应中的两条结论均明确限定“根据所提供的本地功能验收资料”，并使用 `引用位置：lifecycle.txt，正文 · 字符 1–41。`。确定性解析只识别另一种引用排版，将合法定位数字误判为事实数字；修订响应随后丢失资料归因，又被归属门槛拒绝。不是输入乱码或 MinIO 故障，也不是独立语义模型否决了两条结论：该轮尚未进入独立语义核查。

后续源码补齐精确绑定的引用字段格式，并按同一分句识别资料归因，不再依赖任意的八字符距离上限。伪造定位、错误标题、事实数字及无归因的修订仍被阻断，完整结论仍交给原独立语义核查。没有修改提示词或证据标准。[原始响应离线回放](offline-provenance-replay.json)确认两条原始结论现在能到达语义核查入口；它没有调用模型，不能作为新真实流程通过的证据。相关六文件回归 104 项通过，最终定位反例 24 项通过，Ruff 通过。

## 独立完成的安全修复

MinIO 两个程序、Grafana 主程序及十三个插件实际使用固定 Go 1.27.4 重编译，消除新增的 16 条 `GO-2026-6859`／`CVE-2026-97054` 扫描记录。最终正常构建、实际镜像复扫及原门槛通过，详见[安全专属收据](go-security-acceptance.json)。MinIO 原始记录 43→41，另有 34 条 LOW／MEDIUM 未完成全量技术复核；Grafana Trivy 54→40、Grype 保留 10 条，原级别和逐项证据保持，Secret 均为 0。不是 raw zero、全无缓存构建或第三方二进制分发批准，也不能代替失败的真实研究流程。

本轮只提交源码与诚实的阶段证据，不发布新版本、不更新日常镜像。日常 25 个容器与隔离 17 个容器均恢复停止，日常配置、镜像和数据未切换。
