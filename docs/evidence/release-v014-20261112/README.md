# 常规问法与发布安全复验

2026-11-12 对源码修复 `ec6c8e670761f235d307831c799c811761236912` 执行第一轮真实官方模型流程。此前的[失败结果](../release-20261112/default-prompt-insufficient.json)继续保留；本轮使用完全相同的常规问题，没有增加指定句式、禁止定位数字等要求：

> 根据本地功能验收资料，说明工作空间成员权限在哪里校验，以及删除资料后的检索预期。请分别说明两点并给出资料引用，不推测其他功能。

此前的确定性校验把真实来源的字符定位 `1–41` 当作事实数字，又未识别 `《lifecycle.txt》正文明确说明` 的明确资料归属。本次只把实际引用来源的精确书名和绑定定位作为元数据处理；同名文件多个分块先匹配全部完整定位，再处理独立书名，消除来源顺序影响。事实中的数字、单位、否定、来源权限和独立语义核查保持原门槛，完整结论仍送入核查模型。没有修改研究提示词。

[真实结果收据](ordinary-query-acceptance.json)与[原始报告正文](research-report.md)记录了两条结论均支持、无删除、无修订、`insufficient=false`、`original_request_answered=true`。报告仍把资料陈述和实际系统效果分开，没有把“不应出现”改写成已经验证不会出现。浏览器执行资料上传、研究提交、引用核验、删除后检索和 viewer 写入拒绝，1 项通过、0 跳过。

第一轮实际使用 `gpt-6.1-sol` 与 `text-embedding-3-large`，新增 6 次文本请求、3 次嵌入请求，均 HTTP 200。既有 23 次请求及其中 HTTP 400 的预留没有重置；截至该时点，32 次累计全部请求上界预留为 3.547734 USD，处于用户授权的累计 5 USD 上限内。该数字是阶段保守预留，不是供应商账单。私密配置和原始 SQLite 账本留在本机，没有加入源码。

本页第一轮使用新的 Agent 代码快照和旧 MinIO，实际镜像身份逐项保存在收据。最终封装 Agent 与新 Go MinIO 的组合复验、最终累计预算和界面状态另见 [v0.1.4 补充收据](https://github.com/W205614/DeepResearch/releases/download/v0.1.4/final-combination-acceptance.json)，不能把本页第一轮的结果当作最终组合已运行的证据。
