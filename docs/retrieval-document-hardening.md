# 检索与文档边界处理

2026-09-13：在图片输入功能上追加的实现。没有每日查询次数或 Token 配额；模型调用仍受接口上下文长度限制，研究过程保留防止循环和堆积的执行保护。

## 查询限制与服务错误

- 移除 `WORKSPACE_DAILY_SEARCH_LIMIT` 的执行逻辑；旧环境变量不会生效。旧客户端仍可提交 `daily_search_limit`，该字段被忽略，查询接口返回 `null`。管理员仍可设置并发研究数。
- 每轮默认最多 12 次搜索、2 次反思补搜，默认执行时限 600 秒。搜索失败和备用来源切换分别计数；UTC 日台账仅统计，不拒绝后续查询。到达本轮上限显示 `search_limit_reached`，可继续发起研究。旧任务的 `budget_exhausted` 在页面按同一含义展示。
- API HTTP 402 提示账户余额或付款问题，429 提示外部限流，401/403 提示认证/授权问题；其他错误不猜测成“没钱”。错误消息不包含响应正文或密钥。
- PostgreSQL 增量迁移 `0006_search_accounting` 清零旧配额字段、清理旧检索缓存，保留历史使用台账。SQLite 初始化兼容旧库。回退迁移不会自动给用户重新设定配额。

## RAG 字段与片段

| 边界 | 实现行为 |
| --- | --- |
| 缺少片段 ID、ID 不属于当前索引、分数为 NaN/布尔值或超出余弦范围 | 丢弃该条，保留其他有效证据，记录 `invalid_records`；允许合法数值字符串转为数值，不猜测任意字段映射 |
| 向量返回的正文、标题或归属与数据库不一致 | 仅信任来源 ID 和合法分数；正文、定位和归属从当前工作空间的 SQL 索引取得 |
| 缓存损坏或存在无效引用 | 失效后重新检索；正常缓存也重新取得数据库原文，缓存正文不能覆盖来源 |
| 向量或嵌入服务失败 | 保留关键词检索，标记 `vector_unavailable`；降级结果不缓存，下次重新尝试向量服务 |
| 所有可用结果无效，关键词也无结果 | 报检索故障，不能伪装成一次正常空结果 |
| 正常服务返回零相关结果 | 返回空结果；不再把零分资料当作证据。向量最低余弦分默认 0.2，可用 `RAG_MIN_VECTOR_SCORE` 调整，它不是正确率或置信度 |
| 多查询、重复或过多片段 | 查询去重；每次 1–20 个返回片段，最多 8 条子查询；使用 BM25Plus（delta=0）与向量融合及近重复去除 |
| 单一文档占满研究来源 | 按文档、图片或网站来源轮流选取，最多保留 48 个证据候选，之后由 Judge 判断相关性 |
| 模型单次输入过长 | Judge/Analyst/Writer/Repair 的证据文本合计最多 48000 字符，单来源最多 4500；截取优先在行或句末，显式记录 `excerpt_truncated`。原文仍保留供查看和核验 |
| 引用核查过多 | 按最多 12 条结论及约 96000 字符引用原文分批，逐批核查全部结论，批内原文不截短；修订也分批处理 |

研究结果、过程事件及 Grafana 原有兜底分布面板会展示无效字段与向量降级。资料库调试页面也展示降级原因；原来的搜索 API 默认仍返回数组，`?diagnostics=true` 返回 `results/reasons`。

“字段不符合”还可能表示年份、地区、主体、口径不符合问题，这与 JSON 字段缺失不同：来源完整不代表能回答问题。相关性筛选与引用核查继续检查这些语义条件，不会从文件名猜测缺失年份，也不会因相似度高就替换用户要求的地区。没有可核实对应关系时说明缺口。

## 按文件结构解析

| 文件 | 处理 |
| --- | --- |
| TXT | UTF-8/BOM 解码，拒绝二进制控制字符；长段按有重叠的片段拆分，保留尾部 |
| Markdown | 按标题保留章节；标准管道表格逐行携带表头，列数不一致提示修正。复杂转义管道表格建议转 PDF |
| DOCX | 按文档顺序处理段落、表格及图片；表格行/续片段重复表头；嵌套表格、单元格图片、页眉页脚保留定位 |
| DOCX 不支持的结构 | 文本框、嵌入对象、原生图表/SmartArt、脚注、未接受修订等明确提示接受修订或转 PDF；不静默丢弃这些正文内容 |
| 普通文字 PDF | 按页提取布局文本，保留页码 |
| 扫描、图形、疑似双栏或乱码 PDF 页 | PDFium 渲染整页，视觉模型按阅读顺序提取，保留单位、年份、否定词与表格行；不单独抽取碎图片再拼接，不同时重复索引整页 OCR 与同页正文 |
| 独立图片或 DOCX 嵌入图片 | 验证签名、实际解码、动画和像素限制，再解析可见信息。任务附件仍不会自动进入共享资料库 |

视觉解析采用 `readable/text` 结构化输出，格式不符或响应被截断时重试一次；仍失败、内容为空或模型报告无法可靠识别时，资料导入失败。错误定位到页面/图片，并提示上传清晰原件或拆分复杂页面。模型的 `readable` 判断不能代替人工核实。

文件格式错误在上传阶段返回 HTTP 422；扫描服务不可用仍是 503。后续解析或嵌入失败显示“导入失败”，不会发布部分索引。实际文件类型必须与扩展名匹配，改后缀不是格式转换。

保留文件处理保护：单文件 10 MB、PDF 200 页、需视觉解析的页面/图片最多 20 个且合计 20 MB、最多 400 个索引片段；长表头、异常尺寸或复杂内容流明确要求拆分。这些保护限制单次解析工作，不扣减每日查询额度。PDF 渲染长边最多 2000 像素，密集小字可能需要用户提供局部高清截图。

新规则只应用于新导入或手动“重建索引”的资料，不自动改写已有资料。页面“片段”可查看最多 400 个片段。PPT、Excel、任意公式、跨页合并表格和任意排版准确恢复尚无保证；视觉结果须与原件核对，不能包装成外部权威事实。安全扫描处理文件威胁，不等于识别或消除提示注入。

库接口依据：[python-docx 文档顺序遍历](https://python-docx.readthedocs.io/en/stable/_modules/docx/document.html)、[pypdf 文本提取边界](https://github.com/py-pdf/pypdf/blob/main/docs/user/extract-text.md)、[PDFium 渲染接口](https://pypdfium2.readthedocs.io/en/v4/python_api.html)。PDF 渲染提供页面图像，阅读顺序仍需解析策略或视觉模型判断。
