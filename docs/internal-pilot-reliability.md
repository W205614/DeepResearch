# 内部试用可靠性加固

本次变更面向受控内部试用，保留单机架构。容器存活、模型返回有效 JSON、报告存在引用都不等于结果完整正确。

## 已落实的行为

任务总截止时间在接单时持久化，排队、每次执行和人工继续共同消耗该时限。外部 HTTP 尝试在发送前预留调用和 Token 预算，超时或崩溃不返还未知消耗。`reserved_tokens` 是保守的风险上界，不是供应商账单；实际返回的 usage 仍单独记录。现阶段未知分词器按 UTF-8 字节数保守估算，视觉图片单独预留，不把 Base64 当文本 Token。可能提前拒绝本来能装下的请求，不宣称精确计数。

同一配置的身份/余额错误进入持久阻断，临时错误有限重试、退避并遵守合理 Retry-After。长等待直接熔断，不睡满任务时限。熔断键包含地址、模型和凭据的散列，不持久化密钥。冷却后的探测受共享租约限制。没有自动切换到未经批准的模型。

自动恢复最多 `MAX_JOB_RETRIES` 次；业务预算耗尽后停止入队。手动继续不清零预算。研究检查点和中间图写入在执行所有权保护下完成；旧执行不能覆盖新执行。取消表示停止本地后续工作并拒绝迟到结果，不代表供应商一定停止生成或撤销计费。

核验结果按模型配置、指令和完整输入散列保存；恢复复用同一核验批次。部分批次失败时，仅提供有效证据支持且核验通过的结论，任务仍为失败/可恢复，不发布草稿。最终执行状态和 done 事件在同一数据库事务提交，SSE 从持久事件重放，客户端断线后查持久任务状态。

长证据按相关段落选取并保留尾部限定内容；截断明确标记。最终核验使用完整引用原文，超过预算时停止，不能用摘要替代。质量与运行状态分开：`complete / partial / insufficient / unverified / unknown`；普通聊天和图片解读不是已核验研究。问题覆盖由模型辅助判断，仍需人工检查。

向量路径默认 3 秒内返回或降级到关键词；无结果、故障与策略阻止分别记录。关键词计算移出事件循环，并限制工作空间片段数和缓存工作空间数。重建索引时保留旧版供读取，新版完整发布后切换；失败保留未变化的旧版。引用携带片段编号、原文散列和索引版本，恢复和交付前检查有效性。

## 资料外发策略与兼容性

- 新请求 `data_policy` 默认为 `internal`：禁止公开搜索；只有管理员显式设置 `ALLOW_INTERNAL_MODEL_PROCESSING=true` 才允许已配置模型处理内部资料。应先核准 LLM、视觉与嵌入供应商及其数据处理方式。
- `public`：用户声明问题及随附图片可外发公开检索；不加载内部知识库或私有会话历史，避免把内部内容带进搜索查询。
- `restricted`：拒绝外发，不自动换模型或降级成联网问答。
- 历史请求默认内部策略；旧结果质量标记为 unknown。旧证据缺少版本信息时必须重新研究，不能伪造版本来复用。
- 资料上传被视为内部资料。扫描与原文存储可以执行，但外发解析/嵌入必须经过管理员配置许可。此分类依赖用户正确声明，不是自动 DLP 检测。
- API 保留原有接口。错误增加 `error.code/retryable/action/stage/result_unknown`；任务增加 `can_resume`、`error_info`、`recovery`。前端不再通过错误文字决定是否重试。

## 配置与发布

执行 Alembic `upgrade head`，新增迁移为 `0008_reliability`。它为旧记录添加预算和策略默认值，不将历史数据标为已验证。上线前先备份；应用回滚需要保留这次增加的数据库字段，避免直接降级删除预算与核验记录。

| 配置 | 默认 | 用途 |
| --- | --- | --- |
| MAX_RUN_TOTAL_SECONDS | 1200 | 接单到最终交付的累计时限 |
| MAX_RUN_SECONDS | 600 | 单次执行上限，仍受总截止时间约束 |
| MAX_RUN_CALL_ATTEMPTS | 80 | 所有外部 POST 尝试共用的次数上限 |
| MAX_RUN_RESERVED_TOKENS | 2000000 | 保守 Token 风险预算，不是实际账单 |
| MAX_JOB_RETRIES | 2 | 自动恢复次数上限 |
| MAX_QUEUED_RUNS | 20 | 全局待处理任务容量 |
| RAG_VECTOR_TIMEOUT_SECONDS | 3 | 查询嵌入与向量检索的共同等待上限 |
| RAG_MAX_CORPUS_CHUNKS | 4000 | 工作空间关键词检索容量 |
| RAG_CORPUS_CACHE_USERS | 4 | 每进程缓存的工作空间数 |
| LLM_CONTEXT_TOKENS / VISION_CONTEXT_TOKENS | 128000 | 应按实际批准模型核实配置 |
| VISION_IMAGE_TOKEN_RESERVE | 16000 | 每张图片保守预留，需按供应商校准 |

Compose 增加 `document-worker`，新文档任务投递到独立队列，旧队列仍可排空历史文档任务。研究 Worker 限制 2 GiB/2 CPU，文档 Worker 限制 1 GiB/1 CPU；这些是试用起点，不是容量实测结论。新文档 Worker 必须与 API 一起发布。受限进程内的后台线程无法强制杀死；依靠超时停止后续流程和容器资源限制控制损失。

`/livez` 只检查进程；`/readyz` 检查核心数据库；鉴权后的 `/api/capabilities` 返回队列、向量、对象存储和扫描能力。向量故障不摘除历史报告入口。数据库不能确认写入时不返回接单成功；队列不可用时已接单任务仍落库，恢复扫描负责重投，达到积压上限拒绝新任务。

## 运维与恢复

固定角色：业务试用负责人决定哪些资料可外发并人工抽查；值守管理员处理模型配置、积压和备份。正式开放前由团队填写姓名与替班安排。

供应商身份错误：先停止提交，核对配置和账户；更换密钥会生成新的熔断标识。若保留原密钥而在供应商侧修复授权/余额，管理员在维护窗口删除对应 provider_health 阻断记录后再探测，不向普通用户开放重置接口。

监控新增队列最老年龄、持久心跳延迟、运行数据盘剩余空间、供应商阻断和结果质量计数。运行盘指标不代表所有 Docker 数据卷；宿主机仍需监控 Docker 磁盘、内存与各数据卷容量。

另一个主机可执行 `python scripts/probe_external.py --base-url <受控服务地址>`，正常退出为 0，故障为 1。将其接入现有监控系统；脚本不自动发送通知。该探针验证核心服务，不证明所有研究能力健康。

现有 `scripts/backup.ps1` 仍是冷备：拒绝正在执行/索引的任务，停止服务完成一致备份后恢复服务。异机复制使用 `python scripts/copy_backup.py --source <已有备份目录> --destination <已挂载异机的新目录>`，先检查源清单，再核对复制后的所有文件。不会推断远端地址、覆盖已有备份或绕过组织存储授权；目标必须由管理员确认位于另一台机器并配置访问权限/加密。

恢复使用现有隔离恢复脚本，不覆盖当前卷。检查 SQL、账号与权限、报告、附件和可检索数据，记录恢复耗时以及备份时点到故障时点的数据缺口。校验和通过不等于业务恢复通过。

## 放行证据与尚待环境落实项

故障测试入口：`tests/test_reliability.py`；组件演练入口：`python scripts/verify_components.py --drill`，仅使用 `dr-verify` 隔离项目，模型/搜索为可控替身。真实模型使用固定合成题评测，不提交内部业务资料。各类结果分别记录，不相加成总体准确率。

放行前必须确认：预算耗尽确实停止、旧执行/失效权限/失效来源不能发布、降级用户可见、故障时无草稿冒充可信结论、备份在另一环境恢复成功。另行准备未用于改提示的题目和人工盲评；同模型评分不能代替人工审查。

本机无法证明异机备份目的地、独立监控调度、业务负责人、生产网络访问控制或恢复 SLA 已落实。未配置和演练这些项目之前，不应将本次代码交付称为正式生产放行。

## 本轮验证记录

- 后端全量：195 passed、4 skipped；跳过项为隔离组件测试，随后单独运行的 4 项真实组件测试通过，不能把同一套测试重复相加。
- 新增故障测试共 20 项；RAG 与故障组合回归 37 项通过；最后补充单次模型请求绝对超时和探测租期保护后，模型适配层与故障组合回归 36 项通过。覆盖模型限流/授权失败、预算恢复、旧执行、资料版本、关键词降级、部分核验、断线事件、磁盘写入失败和备份复制损坏拒绝。这些组合与全量测试有重叠，不累加计数。
- 前端：12 项单元测试、构建和 1 项浏览器模拟接口场景通过；浏览器场景验证默认内部范围、公开选择、部分报告标识以及预算耗尽不显示继续按钮。它不代表真实 OIDC 端到端复测。
- 隔离真实组件：4 项集成测试通过；最终 Worker 强制终止恢复观察为 53.84 秒；Redis 恢复后持久任务完成；Milvus 中断时 readyz 保持可读且向量能力降级，恢复后能力检查成功。模型与搜索为可控替身，不代表真实模型吞吐或恢复 SLA。
- 隔离逻辑恢复：最终 PostgreSQL dump/restore 校验 5 张表，MinIO 新桶复制并校验 2 个合成对象后清理，耗时 11.53 秒；这是逻辑 SQL/对象恢复，不是整机冷备或跨主机容灾。
- 真实模型：固定研究 30/30、独立回答 10/10、新增保留题 3/3。本轮均一次完整运行；没有用重跑结果替换失败题。同模型图外评分，未人工盲评。模型评测后继续完善了本地来源、Worker 与界面保护，最终离线/组件回归覆盖这些调整；模型运行未保存不可变源码快照，不宣称它们与最终工作树逐字相同。
- Ruff、Compose 配置校验、diff 空白检查通过；Prometheus 8 条规则通过工具校验。未对正在运行的主项目执行迁移、重建或告警重载。
