建议问题：

> 我准备先上线纸桥个人知识库的第一版。请综合资料库里的需求、两次评审和待验清单，判断先用关键词检索还是加入向量的混合检索；把材料里互相冲突或不能直接比较的数字讲清楚，并说明上线前还缺什么证据。

选择“内部资料（不联网）”。资料中的版本和日期用于检验时序比对，不能把旧文本块数写成最新文件数，也不能把平均延迟与 P95 当成同一个指标。案例没有预设唯一推荐方案；有依据的取舍和明确的信息缺口比特定结论更重要。

同一使用场景也可以另开一个“公开问题（联网检索）”：

> 我想做一个个人技术笔记库：约 1,200 份中英混排 Markdown，单机 4 核、16 GB 内存，最多 3 个客户端，需要精确查找故障编号，也要用不同说法找同一问题，并按项目筛选、删除过期笔记。请基于官方资料比较 PostgreSQL 全文检索加 pgvector 与 Milvus 两条路线，说明各自需要怎样组合能力、版本限制和维护代价，再给出第一版的取舍及仍需实测的项目。

联网问题中的规模是使用假设，不是运行测量。公开模式不读取上述本地资料、私有会话或个人记忆。联网结果应以本次实际取回的来源和适用版本为准；仅搜索到链接、读到摘要或引用项目首页，不能算已经核实所有能力。官方功能说明也不能证明这台假设机器上的延迟、内存或检索质量。

本目录提供输入，不提供“已运行通过”的证明。真实运行结果、模型用量、来源正文和截图应另附对应收据；未运行、失败或部分结果要如实说明。
