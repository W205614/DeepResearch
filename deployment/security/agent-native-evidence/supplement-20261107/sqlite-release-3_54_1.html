SQLite Release 3.54.1 On 2026-10-16

Prior changes from version 3.54.0 (2026-10-09):

  1. CLI enhancements:
    1. CLI prompt strings may contain escape sequences that expand to show state information. The initial CLI prompt is now be initialized the values of the SQLITE_PS1 and SQLITE_PS2 environment variables, if those variables exist.
    2. The default CLI prompt has been enhanced to take advantage of the new escape sequences described in the previous.
    3. For columnar output modes, the CLI now shows the column name header by default even if the query returns no rows.
    4. Use the new diskused() extension to implement the ".diskused" dot-command. The replaces the separate sqlite3_analyzer utility program, which is now deprecated.
    5. On unix, the CLI preserves zero bytes when outputing unformatted BLOB values.
    6. Enhance the .mode command with new options "--rowcount on" and "--titles always". The "--titles always" is now the default behavior (see item 3a above). Legacy behavior can be restored using "-titles on".
    7. Enhance the .mode command with the new --ifmt option and --fpfmt option that allow the rendering of integer and floating-point values to be more precisely controlled using a printf-style format string.
    8. The -csv command-line option automatically disables display limits, for legacy compatibility.
    9. The default CLI prompt honors the NO_COLOR environment variable.
    10. The ability to end an SQL command using the line that contains just "go" or "/" (for compatibility with SQL Server and Oracle, respectively) is discontinued, unless the CLI is compiled with option -DSQLITE_SHELL_LEGACY_COMMAND_TERMINATOR.
  2. Query planner improvements:
    1. When doing an UPDATE on a table that has expression indexes, do not change the expression index if the value being indexed is unchanged.
    2. Improved optimization of "expr OR TRUE" and "expr OR FALSE".
    3. Ignore DISTINCT in the SELECT statement on the right-hand side of an IN operator.
    4. UNION queries with a LIMIT of exactly 1 are now handled faster and with less memory.
  3. The ALTER TABLE command raises an error on any attempt to add, drop, or rename columns with the special names "ROWID", "_ROWID_", or "OID".
  4. Add the diskused() SQL function as an optional extension.
  5. Added the %J and %j conversions used to render JSON string literals to the built-in printf() and the format() SQL function.
  6. Add the sqlite3_result_str() interface and use it internally to simplify the code.
  7. Add the sqlite3_incomplete() interface and use it as part of the newly enhanced CLI prompt string management.
  8. Enhancements to date/time functions:
    1. Added the "weekday -N" form of the weekday modifier.
    2. Added the end of modifier.
  9. Use O_TMPFILE when generating temporary files, on systems that support that feature.
  10. Drop support for WindowsXP and earlier Windows versions, including WindowsCE. SQLite for Windows now requires Windows Vista (circa 2007) or later.
    1. Improve performance by using Slim Reader/Writer Locks (SRWLs) to implement non-recursive mutexes, instead of CriticalSection, since all supported Windows platforms now provide SRWLs.
    2. Use the -DSQLITE_UWP=1 compile-time option for UWP and WebUI applications.
    3. To be clear: This changes above only affects SQLite on Windows. Builds for Linux, Mac, BSD, and other unix variants are unaffected.
  11. The authorizer callback is now invoked for SQL functions found in the DEFAULT clauses of CREATE TABLE statements. This happens both when the CREATE TABLE statement is first issued and when the DEFAULT value is actually used, but not when reading the schema while opening a database.
  12. Added SQLITE_LIMIT_SCHEMA and SQLITE_LIMIT_TRIGGER_STEPS to the sqlite3_limit() interface.
  13. About 4% faster, as measured by counting CPU cycles in the speedtest1 preformance benchmark using valgrind on Linux x64. About 7.5% faster compared to one year ago (version 3.51.0). Your mileage may vary depending on workload, build options, CPU, compiler, and operating system.

Changes in this specific patch release, version 3.54.1 (2026-10-16):

  1. Fix a possible heap-buffer overflow on 32-bit builds. (64-bit builds are not affected by this problem.)
  2. Fixes other problems in 3.54.0 reported by users. See the check-in timeline for details.
